# Outbound Messaging

## Purpose
How replies are sent back to channels.

## Findings

### Outbound Flow

```
Agent generates reply text
  -> src/agents/command/delivery.runtime.ts
    -> channel-specific send function
      -> channel plugin API call
        -> external service (WhatsApp/Telegram/Discord/etc.)
```

### Delivery Runtime

- File: `src/agents/command/delivery.runtime.ts`
- Queues outbound messages per channel
- Handles rate limiting and retry logic
- Formats message for channel-specific constraints

### Channel-Specific Send Constraints

| Channel | Max Length | Markdown | Media | Typing Indicator |
|---------|-----------|----------|-------|-----------------|
| WhatsApp | 4096 | Limited | Yes | No |
| Telegram | 4096 | Full | Yes | Yes |
| Discord | 2000 | Full | Yes | No |
| Slack | 4000 | Full | Yes | No |
| Signal | Unlim | Limited | Yes | No |
| iMessage | Unlim | No | Yes | Yes |

### Message Splitting

- Long messages split into multiple sends if exceeding channel limit
- `src/agents/command/delivery.runtime.ts` — split logic
- Preserves markdown formatting across splits
- Code blocks kept intact when possible

### Media Outbound

- Images generated by agent uploaded as attachments
- `src/media/store.ts` — media storage and retrieval
- Temporary URLs served via gateway (`/managed-image-attachments/*`)
- Channel plugin downloads and re-uploads to external service

### Typing Indicators

- Supported channels show typing indicator during agent processing
- `src/channels/plugins/typing-indicator.ts` — typing indicator utility
- Automatically disabled for fast responses (< 1s)

### Retry & Error Handling

- Failed sends retried with exponential backoff
- Permanent failures logged to task registry
- Some channels (WhatsApp) may require reconnection before retry
- `src/infra/outbound/delivery-queue-storage.ts` — queue persistence

### Delivery Queue Storage

- File: `src/infra/outbound/delivery-queue-storage.ts`
- Persists outbound queue to disk for crash recovery
- SQLite-backed for reliability
- Processed asynchronously to not block agent runtime

## Evidence
- `src/agents/command/delivery.runtime.ts` — delivery logic
- `src/infra/outbound/delivery-queue-storage.ts` — queue persistence
- `src/media/store.ts` — media handling
- `src/channels/plugins/typing-indicator.ts` — typing indicators
- `extensions/*/src/channel.ts` — channel-specific send implementations

## Notes
- Outbound delivery is asynchronous — agent does not wait for send confirmation
- Some channels (WhatsApp) have strict rate limits that are respected
- Media outbound may fail silently if external service rejects file
- Delivery queue ensures no messages lost during gateway restart
